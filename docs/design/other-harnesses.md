# Codex and Antigravity harness adapters

Research snapshot: 2026-11-12; Harnessgram (`ctb`), local revision `cc7fffb`.
**Recommendation:** retain the Claude implementation behind an adapter; add Codex reply/progress observation plus native message queuing first, then an agy stream adapter. Use native control protocols for later approval support, rather than porting Claude's terminal parser.

Scope: local source, installed help, selected non-secret configuration fields, and structural inspection of existing session records only. No model runs, authentication files, network research, installs, settings changes, or live message injection. HEAD equals the **cached** `origin/main`; remote freshness was not verified because this investigation is local-only. The usual worktree doctor was not run because its stale fetch cache would trigger a network fetch. Only this document is added.

## 1. Claude dependencies and hook equivalents

The installed hook inventory is authoritative at `src/ctb/install.py:48-64`. Its command hooks consume JSON on stdin and emit JSON on stdout (`src/ctb/hooks.py:1-5`). Shared fields include `session_id`, `transcript_path`, `cwd`, and, for lifecycle dispatch, `hook_event_name`. Similar event names in another product do **not** establish payload or return-value compatibility.

Evidence labels below: **observed** = local help/configuration/record structure; **documented** = installed product documentation; **candidate** = compiled symbol or integration inference, not an exercised contract. “Not established” means this investigation found no sufficient contract, not proof the product lacks the feature. Local evidence references C1–C4 and A1–A4 are defined in section 2.

Codex's `exec --json` stream and saved rollout are **different formats**. Prefer the stream for bridge-launched exec jobs; use a versioned rollout parser for opted-in existing sessions. Mirror only assistant commentary/final output, never developer/system instructions, raw reasoning or encrypted content. Where both a response item and completion summary contain the answer, choose one canonical representation and deduplicate by native thread/turn/item identity. Paginated history and `--ephemeral` sessions need separate discovery/replay handling; filesystem tailing cannot promise universal coverage.

For agy, prefer `result.response` for completed print turns and `step_update` for progress until a complete transcript schema is validated. Do not assume `content` in any transcript row is an assistant reply. ACP permission/update method symbols also occur in the binary, but help plus symbols is insufficient to promise request/response behavior or attachment to an already-running TUI.

## 3. Small adapter boundary and delivery plan

Use a small `Harness` protocol, keeping parsers/control transports inside each implementation:

| Contract | Responsibility |
| --- | --- |
| `capabilities()` | Versioned flags: discover, observe, send, steer, interrupt, resume, tool approvals, user questions, children, usage. Unknown/unsupported is explicit. |
| `discover() -> Session[]` | `SessionRef=(harness, profile, native_id)`; cwd, title, model, optional parent, liveness provenance. Discovery does not opt a session into forwarding. |
| `events(ref, cursor) -> Event[]` | Typed `TurnStarted`, `AssistantText(phase, final)`, `ToolProgress`, `TurnEnded(outcome)`, `NeedsInput`, `Usage`, optional `ChildState`; native turn/item/request IDs, timestamps and durable cursors. |
| `send(ref, message) -> Receipt` | Preserve owner/team/forwarded/voice/button provenance and framing. Receipt distinguishes locally queued, native queue accepted, transcript-observed ingestion and answered; no false “delivered” on exit 0. |
| `control(ref, command)` | Typed start/resume/interrupt, and later request-bound input/approval response. Reject unsupported operations; never fall back to guessed keystrokes. |

Implement `ClaudeHarness` by wrapping the current behavior first, preserving raw UUID-keyed legacy state through a migration/lookup layer. Centralize registry and event reduction above existing inbox/topics/mirror/progress. Move transcript/model/account lookups out of Cockpit and session collectors into normalized snapshots; radio then consumes those snapshots. Keep Telegram authentication, routing, credential filtering, translation and delivery policy shared.

Adopt the CLIs' existing protocols/streams; do not build another terminal scraper. Codex app-server is the promising richer control surface; agy ACP is the promising cross-client surface. Avoid forcing both into ACP when no local Codex ACP command was established. Revisit external wrappers only after official surfaces leave a demonstrated gap.

| Stage | Included | Explicit limits / acceptance |
| --- | --- | --- |
| Codex MVP | Opt-in attachment to an existing local persisted session; mirror final replies and selected commentary; coarse busy/idle/error and tool progress; native queue injection by exact UUID; model/usage when observed; basic Cockpit/radio state. Optional owned `exec --json` jobs use a separate parser. | No remote tool approval, TUI/menu control, automatic account moves, guaranteed mid-turn steering or full subagent/media/log parity. Queue errors remain visible; queue acceptance is not ingestion. Never resume the same thread concurrently through exec to inject into a live session. |
| Codex richer control | Validate app-server schemas/version and whether a client can attach to the existing shared daemon; then implement steer, interrupt, user questions and request-bound approvals where supported. | Keep approvals off until real round-trip, stale-request, disconnect and owner-auth tests pass. A separate server must not silently become a second writer of the same thread. |
| agy MVP | Owned print/stream process; final `result.response`, step progress, conversation resume; sequential stdin turns after verifying the input envelope. Adapter-managed startup can bind conversation identity. | Existing arbitrary TUI attachment and complete passive transcript mirroring remain unverified. Hooks can supply observation/context at supported boundaries, but cannot wake a fully idle agent asynchronously. |
| agy richer control | Validate ACP session loading, streaming, cancel and permission responses; add child mapping only with authoritative parent evidence. | Local help does not prove shared ownership with a live TUI, account-level access, or child-event coverage. |

**Approvals:** preserve current provenance and fail-closed behavior (`src/ctb/framing.py:8-18,37-52`), while replacing Claude-specific app wording in new-harness paths. Native approvals must bind authenticated owner, harness/profile/thread, turn, exact request and action, expiration, and one response. An assistant's conversational “yes” handling is not a tool-approval transport. Never select bypass flags or weaken the session sandbox to make headless runs work. The local agy wrapper explicitly anticipates denied headless shell calls (a local Antigravity wrapper script); a CLI mode flag is not proof the account permits it.

**Not possible through the proposed MVP surfaces:** answering native approval RPCs through `notify` or a read-only transcript; reliably injecting into an arbitrary agy TUI through an unrelated print process; proving consumption from a queued-message acknowledgement alone; reproducing Claude's async wake with agy's synchronous hooks. These limits do not rule out later native-protocol integrations.

### Effort and principal risks

Estimates are engineering days for one implementer with independent review, not elapsed-time promises; account access and undocumented contracts can extend them.

| Work | Estimate | Main risk / release proof |
| --- | --- | --- |
| Shared boundary, legacy migration, Claude regression coverage | 2–3 days | Preserve existing session routing and security behavior; mixed-harness IDs must not collide. |
| Codex MVP, including observation/queue/restart proof | 3–5 additional days | Rollout/exec schema drift, paginated history, incomplete tails, duplicate completion text, process liveness. Use sanitized fixtures plus an opted-in canary. |
| agy stream MVP and input-envelope proof | 2–4 additional days | Stream completion/error semantics, resume ownership, permission denial, incomplete transcript projection. |
| Native control and approvals | 3–6 additional days **per harness** after protocol spike | Experimental APIs, shared-daemon access and request identity; no estimate of guaranteed parity before the spike. |

Minimum guards before release: restart/cursor replay without duplicate replies; UTF-8 partial records and file replacement; final-vs-commentary/tool distinction; late completion from an older turn; failed queue send and accepted-but-unobserved delivery; same native ID in different harness/profile; disconnected/stale approval refusal; child events cannot drain the parent's inbox; mirror-off and egress sanitization preserved. No extra model runs are necessary for parser fixtures. Roll out one opted-in session first, then verify Telegram reply, inbound ingestion, Cockpit and radio separately.
